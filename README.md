# Fake_Data_testing

Practice project on **quantitative survey data**: how a raw online-survey export
is checked, cleaned and analysed before any real conclusions are drawn.

> **All data in this repository is synthetic.** It was generated by a script with
> a fixed random seed. It contains no real people and no real study results, and
> the findings say nothing about the real world.

## Why this project exists

I want to work as a data analyst. Online surveys (for example on platforms such
as Prolific) deliver messy data: duplicates, rushed answers, inattentive
respondents, missing values. I built this project to practise the full path
from raw export to first statistics, with every decision documented.

## Structure

| Folder | What it does |
|---|---|
| [`01_survey_data_cleaning`](01_survey_data_cleaning) | Generates a messy fake survey export and cleans it step by step, with a log of every removal |
| [`02_descriptive_statistics`](02_descriptive_statistics) | Describes the cleaned sample, checks scale reliability and runs first statistical tests |
| [`data`](data) | Created when you run the scripts: `raw_survey.csv` (generated) and `clean_survey.csv` (cleaned). Not committed, because the seeded generator reproduces them exactly |

## The fake survey

A questionnaire on *digital competence* and *perceived workload burden* at work,
about 500 working adults:

- 4 Likert items (1-5) for digital competence (`dc1`-`dc4`)
- 4 Likert items (1-5) for burden (`burden1`-`burden4`)
- Demographics: age, gender, sector, years of experience
- Completion time, an attention-check item, a consent question
- Number of times colleagues asked for IT help per week

## How to run

```bash
pip install -r requirements.txt

python 01_survey_data_cleaning/generate_fake_survey.py
python 01_survey_data_cleaning/clean_survey.py
python 02_descriptive_statistics/descriptive_analysis.py
```

Charts are saved to `02_descriptive_statistics/charts/` when the last script runs.

## Skills practised

- Pandas: filtering, grouping, missing-value handling, reproducible pipelines
- Survey data quality: duplicates, speeders, straightliners, attention checks, consent
- Descriptive statistics, Cronbach's alpha, Pearson/Spearman correlation, one-way ANOVA
- Documenting decisions so someone else can reproduce the results

## Limitations and next steps

- Thresholds (for example the 120 s speeder cutoff) are illustrative. In a real study
  they should be set from pretest completion times and documented in advance.
- Synthetic data cannot show how real respondents behave.
- Next: rebuild the same pipeline in SQL and Power BI, and apply it to a public
  survey dataset.
